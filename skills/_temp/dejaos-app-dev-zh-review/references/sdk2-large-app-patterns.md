# SDK 2.0 大型应用模式

## 分层

推荐职责：

```text
main.js
  -> 创建 Worker

UI Worker
  -> 页面、输入、展示

业务/MQTT Worker
  -> 业务流程、命令路由、服务同步

设备 Worker
  -> UART、锁控、GPIO、刷卡、扫码

人脸 Worker
  -> 摄像头、识别、注册

SQLite Service
  -> 数据访问和迁移
```

不要为了文件数量拆 Worker。只有需要独立运行时职责、原生组件所有权或隔离故障时才拆分。

## EventBus

- topic 使用稳定命名，例如 `ui/action/open-lock`、`device/lock/state`。
- 请求载荷带业务 ID、时间戳和必要上下文。
- 需要返回值时带 correlation ID 和超时。
- 接收方对重复消息幂等。
- 不在消息中传递函数、原生句柄或大图片。

## UI 状态桥

- Worker 中的业务状态不能作为 UI 共享对象。
- 业务 Worker 发布可序列化状态快照或增量事件。
- UI Worker 在本地维护显示状态。
- 页面重新显示时可请求一次完整快照，避免漏事件。
- UI 操作先显示“处理中”，收到明确结果后再显示成功。

## SQLite Service

- 统一拥有数据库连接。
- 对外暴露业务方法，不让页面或 MQTT 路由写 SQL。
- 启动时顺序执行 schema 迁移。
- 多步写入使用包装器实际支持的事务方式。
- 把本地记录状态设计为可恢复的状态机。

## 配置服务

- 默认值、持久化值和服务器下发值按明确优先级合并。
- 写配置时校验类型、范围和枚举。
- 关键配置变化通过 EventBus 通知使用方。
- 密钥、令牌和设备身份不要打印到日志。

## MQTT 命令

1. 解析 topic 和 payload。
2. 校验设备 ID、命令类型、时间戳和必填字段。
3. 生成或读取业务命令 ID。
4. 检查重复命令。
5. 路由到业务或设备 Worker。
6. 收集明确结果。
7. 发布确认或错误。

不要让任意远程 payload 直接成为 UART 字节或 SQL。

## 人脸和身份流程

- UI 请求识别或注册。
- 人脸 Worker 管理摄像头及 `dxFacial`。
- 业务 Worker根据识别结果查询权限。
- 设备 Worker执行开锁等动作。
- UI 展示每个阶段的状态。
- 事件和数据库记录使用同一业务 ID 关联。

## 锁控协议

- UART 字节协议隔离在 driver/parser。
- 校验帧头、长度、命令、校验和及地址。
- 业务层使用 `openCompartment(id)` 等领域方法，但只有当 driver 真正实现时才能调用。
- 把发送、设备确认和物理状态变化区分为三个阶段。

## 异常处理

- 每个 Worker 顶层捕获未处理错误并用 `dxLogger` 记录。
- 外部输入错误不使 Worker 崩溃。
- 重连和重试有次数或时间边界。
- 无法恢复时进入明确降级状态，不用无界循环掩盖故障。
- 看门狗复位前尽可能保留可诊断状态。
