# 人脸应用规则

## 实时预览和图层

- 人脸摄像头实时画面默认全屏显示在屏幕最底层。
- 普通 UI 页面位于其上方；不透明根背景会完全遮住摄像头画面。
- 需要完整预览时，把覆盖画面的上层 UI 根背景设为透明。
- 只需要局部摄像头区域时，可使用带透明窗口的背景图，或让对应 UI 区域透明。
- 透明设计必须同时检查文字、按钮和状态层的可读性。

## 识别体验

- 使用人脸识别时默认显示实时画面，帮助用户调整距离、角度和位置。
- 如果产品明确要求隐藏预览，记录该决定及替代反馈。
- 是否显示检测框或追踪框由具体产品体验决定，不是强制项。
- 追踪框必须与摄像头坐标、屏幕旋转、缩放和透明窗口区域一致。

## 注册

- 人脸注册期间必须调用：

  ```js
  dxFacial.setStatus(true)
  ```

- 注册期间不能传 `false`，否则注册不能正常工作。
- 进入注册状态、采集特征、保存业务记录和退出注册应有明确状态机。
- 特征提取、照片保存和数据库写入发生部分成功时要处理回滚或可恢复状态。

## SDK 2.0 初始化

- SDK 2.0 通常由 `dxFacial` 包装摄像头、图像管线和人脸引擎的组合能力，在人脸 Worker 中初始化一次 `dxFacial`即可。
- 不要把 SDK 4.0 的 `dxCapturer`、`dxIvcore` 和 `dxDisplay` 初始化模板直接复制到 2.0。
- 如果目标 2.0 项目安装的包装器或设备文档明确要求其他组件，以该项目证据为准。
- 人脸 Worker 拥有 `dxFacial` 及其回调，避免多个 Worker 重复初始化。

## SDK 4.0 初始化

SDK 4.0 把旧版中由人脸组件内部统一处理的能力拆成多个公开组件。对需要实时摄像头、底层预览和人脸识别的完整链路，至少检查：

- `dxCapturer`：初始化 RGB/NIR 摄像头采集通道。
- `dxIvcore`：初始化图像/视频处理和 G2D 基础。
- `dxDisplay`：初始化显示与实时预览链路所需的显示能力。
- `dxFacial`：在前置图像链路就绪后初始化人脸检测、识别和特征库。
- `dxSystemBus`：作为 SDK 4.0 基础组件安装，供上述包装器内部使用；App 不直接初始化或调用它。

`face_app` 工程当前使用的顺序是：

```text
dxCapturer.init()
  -> dxIvcore.init()
  -> dxDisplay.init()
  -> 注册 dxFacial recognition/detection 事件
  -> dxFacial.init(options)
  -> dxFacial.setConfig(...)
  -> dxFacial.setStatus(true)
```

这是已检查工程的实际链路，不是可以跳过项目包装器校验的固定函数模板。目标项目的导出、参数、返回值和顺序仍以其 `dxmodules/` 为准。

### dxCapcal 边界

- `dxCapcal` 不是 SDK 4.0 人脸识别、实时预览或人脸注册的必需组件。
- 仅在产品需要摄像头标定，且目标项目安装的 `dxCapcal.js` 与当前 SDK/原生库兼容时才导入和初始化。
- 不要因为项目中存在标定 driver 占位文件，就把 `dxCapcal` 加入默认人脸链路。

## 事件和启动

- SDK 4.0 只有在项目包装器定义时才使用 `dxFacial.on/off/once`。
- 包装器通过系统总线分发原生事件时，在 `dxFacial.init()` 前注册事件，避免漏掉早期识别或检测事件。
- `detection` 通常是高频事件；不显示追踪框时不要做无意义的业务转发。
- 前置图像链路任一必需组件初始化失败时，不继续启动 `dxFacial`；明确降级或停用人脸功能并记录错误。
- 所有回调、特征提取、比对、增删特征和状态方法必须对照目标项目对应的 `dxmodules/*.js`。

## 清理

- 页面或流程退出不一定等于销毁组件；根据产品需要区分暂停识别和彻底反初始化。
- SDK 2.0 销毁时先停止识别、取消回调，再按 `dxFacial.js` 反初始化。
- SDK 4.0 按依赖的相反顺序清理：停止人脸状态、取消事件、反初始化 `dxFacial`，再清理显示/图像管线、`dxIvcore` 和 `dxCapturer`。
- 只调用项目包装器实际存在的清理函数；例如 `dxDisplay` 没有 `deinit` 时，不得虚构 `dxDisplay.deinit()`。
- 不保留重复监听器、无界图片缓存或失去所有权的定时器。

## 真机检查

- 摄像头预览实际可见，没有被根 View 遮住。
- 局部透明窗口位置和尺寸正确。
- 人脸移动时画面与可选追踪框一致。
- 注册期间日志能证明 `setStatus(true)` 已建立。
- 无模块加载、摄像头、特征提取或数据库错误。
- 静态检查不能替代真机摄像头和注册体验验证。
