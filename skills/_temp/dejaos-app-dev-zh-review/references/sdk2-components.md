# SDK 2.0 组件开发提示

## 目录

- app.dxproj
- 日志与导入
- SQLite
- UART
- 网络和 MQTT
- HTTP
- 看门狗
- 资源

## app.dxproj

- 用 `dejaos new` 创建，用 `dejaos edit` 或有意识的文本编辑调整。
- 修改组件后执行 `dejaos install`。
- 保留 `model` 和 `mainModel`：前者是真实设备型号，后者用于组件下载。
- 不从其他型号的示例复制 SDK ID 或组件版本。
- `assets/sdk2/` 示例只用于理解结构。

## 日志与导入

- 使用 `dxLogger`，不要使用 `console.log`。
- import 路径按当前文件深度相对指向 `dxmodules`。
- 每个 Worker 独立导入其需要的模块。
- 不假设 Node.js API、npm 包解析或浏览器全局对象存在。

## SQLite

- 数据库默认根目录按主型号决定：VF 主型号使用 `/data`，其他使用 `/app/data`。
- 用独立 service 包装建表、迁移、查询和事务。
- UI 不直接拼接 SQL 或管理数据库句柄。
- 限制查询结果和缓存大小。
- 处理首次建库、损坏、磁盘空间不足和写入失败。
- 具体打开、执行、查询、事务和关闭方法以项目 `dxSqliteDB.js` 为准。

## UART

- 一个 Worker 明确拥有每个串口实例。
- 初始化参数、串口编号、波特率、数据位、校验位和停止位以设备配置及包装器为准。
- 把粘包、拆包、校验和超时放进协议解析层。
- 限制接收缓冲区，遇到无效帧能够重新同步。
- 业务代码不直接依赖原始字节偏移，先转换为领域事件。
- 发送失败、无响应、CRC 错误和设备离线分别记录。

## 网络和 MQTT

- 先根据 SKU 排除不存在的 Wi-Fi 或 4G。
- 以太网、Wi-Fi 和 4G 的初始化与状态 API 可能不同，逐项查 `dxNetwork.js`。
- MQTT 连接、订阅、发布、重连和销毁都由网络 Worker 管理。
- topic 路由转换为明确业务命令，不在 MQTT 回调中直接操作 UI。
- 为重连使用有上限的退避。
- 离线事件队列使用持久化、唯一 ID、最大容量和幂等处理。
- 连接成功不等于业务服务已就绪；订阅和认证失败要单独处理。

## HTTP

- 设置连接和请求超时。
- 校验状态码、响应类型和结果结构。
- 限制响应体和下载文件大小。
- 文件下载先写临时文件，校验后再替换正式资源。
- 处理 DNS、连接、TLS、服务端状态、解析和本地写入错误。
- 所有函数名和返回值以项目 `dxHttpClient.js` 为准。

## 看门狗

- 看门狗只能证明喂狗路径运行，不能证明全部业务健康。
- 初始化、喂狗周期、停止或销毁方法查 `dxWatchdog.js`。
- 不用一个永久成功的空定时器掩盖其他 Worker 卡死。
- 记录重启原因和关键启动阶段，便于日志诊断。

## 资源

- 项目文件放在 `resource/`。
- 运行时使用 `/app/code/resource/...`。
- UI 字体固定为 `/app/code/resource/font/font.ttf`。
- 图片尺寸、颜色格式和内存占用应符合设备屏幕和解码能力。
- 缺失资源必须在启动日志中明确报错。
